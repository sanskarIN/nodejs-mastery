# Public repository roadmap

> 📘 **Complete 125-part eBook:** https://ramsandesh.gumroad.com

This roadmap applies to the public companion-code repository, not to the commercial manuscript.

## Completed milestones

### v1.1 — repository hardening

- Cross-platform editor and Git normalization.
- Runtime pinning, CODEOWNERS, Dependabot, CodeQL, and dependency review.
- Dynamic numbered-project discovery.
- Metadata, storefront, security, SBOM, and commercial-boundary checks.
- Architecture, testing, troubleshooting, FAQ, security, and release documentation.

### v1.2 — supplemental learning labs

- Added 12 clearly labeled post-series Node.js laboratories.
- Added dynamic supplemental discovery, tests, demos, verification, challenges, and policy enforcement.
- Extended SBOM and repository checks to the 22-project public code inventory.
- Preserved the distinction between authentic/reconstructed numbered companions and new supplemental projects.

### v2.0 — maintained runtime and quality baseline

- Removed EOL Node.js 20 from the support contract.
- Required Node.js 22+ package metadata, Node.js 22/24 CI, and Node.js 24 development/release pinning.
- Added repository-wide JavaScript syntax, JSON parsing, and runtime-policy gates.
- Required deterministic demos in normal CI in addition to tests and verification gates.
- Added complete runtime-support and quality-assurance documentation.

## Future maintenance

- Add authentic historical companion archives if they are recovered.
- Clearly label any future reconstruction as reconstructed rather than recovered.
- Add regression coverage whenever a reproducible bug is fixed.
- Track official maintained Node.js release lines and update support deliberately rather than automatically.
- Keep CI green on the documented supported runtime matrix.
- Improve examples without turning educational labs into hidden frameworks.
- Review security, dependency, SBOM, and GitHub Actions automation regularly.
- Add new supplemental labs only when they have a distinct learning purpose and pass the supplemental standard.

## Explicit non-goals

- Publishing the paid PDF/DOCX/EPUB in the public repository.
- Inventing missing historical source archives and presenting them as originals.
- Adding production credentials, secrets, proprietary datasets, or customer data.
- Claiming that an educational in-memory lab is a production deployment.
- Adding changeable X/Twitter profile links to evergreen documentation.
- Adding person portraits/profile avatars to supplemental promotional assets.
- Creating empty/no-op commits solely to increase commit count.

## Storefront continuity

Public repository documentation should continue to point readers to the official complete edition at **https://ramsandesh.gumroad.com**.
